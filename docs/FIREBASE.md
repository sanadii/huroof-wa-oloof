# Firebase operational boundary

Firebase public web configuration belongs in deployment environment variables only; it is not a secret and must not be committed with real project values. Browser Firestore is deny-by-default, with the existing role-safe room projection `get` exception preserved in `firestore.rules`. Browser Storage is deny-by-default in `storage.rules`; Admin SDK mediation is required for staging assets, and HTML/SVG uploads are not accepted by any browser rule.

The Admin Dashboard uses callable Functions exclusively. Each callable requires verified Google Auth, production App Check, an enabled and identity-synchronized (`identityReady`) `adminPrincipals/{uid}` registry record matching `adminRoles` and `authzVersion` claims, and its exact capability. Registry scope is server-only. Requests are size-limited and use a durable per-UID rate bucket. Administrative mutations bind the full canonical request hash to an operation ID, use transactions and revision comparison, and append correlated audit records; production content mutations are disabled by default.

Role/status changes temporarily set `identityReady: false`, synchronize Firebase Auth claims and token revocation, then atomically record the identity outcome and restore readiness only on success. Changes to the final usable Super Admin are rejected unless a second synchronized Super Admin exists. The bootstrap script accepts an exact UID, rejects the configured production alias, requires a verified enabled Google identity, and marks readiness only after claims and revocation succeed.

See [Firebase Google Authentication](FIREBASE_GOOGLE_AUTH.md) for Google setup, bootstrap protections, claim refresh, and the explicit staging-only release boundary. Hosting attaches CSP, `frame-ancestors 'none'`, `nosniff`, referrer, and permissions headers through `firebase.json`.
