### Prioritized findings

1. **P1 — failure recovery can reopen an already disclosed answer.** `src/features/game/domain/lifecycle.ts:156–158` distinguishes initial wrong answer, opponent chance and terminal QUESTION_FAILED; RETRY_CELL moves back to QUESTION_READING without content replacement. `server/service.ts:255,280` simply reopens the buzzer and retains activeQuestion. `functions/src/game.ts:119` does the same. Both public projection implementations reveal the canonical answer in QUESTION_FAILED (`server/service.ts:332`, `functions/src/game.ts:32`). Therefore terminal retry currently asks the same now-known question. Existing `functions/src/game.test.ts:110` and `tests/game/service.test.ts:200` assert timer restart, without asserting a new question or changed numbered-cell letter.
2. **P1 — the requested category game does not exist yet.** `src/features/game/domain/board.ts:2–12` supports only letter/surprise cells; runtime safe-board shape likewise only supports those kinds. `setup-options.ts` calls classic/fast/custom “mode”; modality is a separate classic/image/charades field. Host creation currently fixes modality to classic (`GameRoutes.tsx` create request) and categories are question filters. `question-selector.ts:45–113` requires letter queues with 25-letter coverage and concept reserves, then selects by letter. A category mode cannot be implemented by renaming setup buttons.
3. **P1 — numbered Huroof surprises cannot rotate today.** `board.ts:revealSurprise` explicitly rejects an already revealed letter. The local service consumes its surpriseLetters queue once on reveal; failure/retry/return never changes the revealedLetter. Introduce an explicit, audited terminal-resolution operation rather than weakening revealSurprise's invariant globally.
4. **P1 — baseline verification has drift.** `tests/e2e/visual.spec.ts` still expects a player-name input on `/` and nine home regions; T-11 moved name entry to `/room/:code/join`, and current entry snapshot has the spatial hero. Treat the name-selector mismatch as source-confirmed test drift; establish the actual current region count before changing that assertion. The previously recorded Firebase 90-second game-flow timeout is historical/open evidence, not reproduced by this review. T-14.1 owns its repair and baseline; do not duplicate that work in T-15.
5. **P2 — lobby hierarchy is too tall for its next action at 1280×720.** In the captured real local lobby, a large code/title slab and tall empty rosters push Start below the initial viewport. The board preview occupies a third roster column, while the actual task is sharing, joining and readiness. A compact code/share strip, two clear team rosters, explicit host-only status and reachable Start would better satisfy 0007. Empty rosters render duplicated color wording in accessible headings (“الأحمر الأحمر”); clean that copy without changing axes. This is a bounded screenshot observation, not a claim across all sizes.
6. **P2 — entry already has a coherent visual identity, but joining is secondary below the hero.** The 1280×720 entry capture is dominated by the authentic board and cobalt set. Preserve this approved identity; improve the join affordance/scroll target and compact return-player path rather than replacing the homepage. Name-entry and room-code form should share error/focus/loading semantics and remember the room intent through recoverable failures.
7. **P2 — audience layout is the strongest current surface.** The live local display capture has a dominant frontal board, correct green-left/red-right score placement, clean numeric hierarchy and restrained stage. Preserve it. Category labels and long questions create a new legibility risk; supply mode-aware two-line cells, a full active-category label, and question/media-safe composition without shrinking all text. Current waiting/round-setup phase copy should distinguish “waiting for host” from “choose question” on noninteractive audience display.
8. **P2 — admin needs workflow-specific treatment.** `AdminRoutes.tsx:20` renders raw inventory keys; list surfaces at lines 23–40 share generic rows and JSON details. Filtering is honestly labelled as within loaded pages and uses JSON.stringify, so it is not global search. Preserve that truth or implement a properly indexed scoped query after database review. Questions, reviews, releases and rooms need dedicated columns, Arabic statuses, visible paging/filter counts, usable detail summaries and targeted recovery. The editor already retains text on save conflict, but uses raw category IDs and generic validation/submission feedback. Improve category selection, field-level errors, source grouping, unsaved-change handling and review reasons. Do not make gated publication/signing appear available.
9. **P2 — motion is present but not a complete event vocabulary.** CSS already has 700ms home entry, finite near-win/winning pulses and reduced-motion handling. Add state-derived press, reveal, failure-to-replacement, roster update and phase-change feedback consistently. Never animate network guesses or retrigger wins on reconnection.
