## Authority and verified baseline

The user requested category view/edit and a way to inspect every question in a category, including question/answer text and media, difficulty, and related information on `/admin/categories`. This is authorized implementation work, following the existing admin design and immutable-release architecture. The current list links only to a short category detail; published questions are in a separate filtered, paginated server query. Published category/question records are immutable. `adminCategoryMetadata` is a separate authoring collection, and production admin mutations are staged. No published question in the captured T38 release has a `difficulty` property; the UI must say that honestly. Existing media preview is verified and capped at 1 MB.

**Decision T39.D1:** Edits are correction drafts for review and a successor immutable release, never in-place writes to an active release. The user was asked whether edits should be immediate or reviewed; no answer arrived during the independent inspection milestone, so the reviewed model is the stated working assumption and can be adjusted if the user replies. The database review is complete. Do not label an `adminCategoryMetadata` save as a player-visible change.

**Visual contract:** Reuse the existing admin surfaces: calm Arabic cobalt/navy/ice, IBM Plex Arabic, density 5/10 desktop and 4/10 mobile. The category title and question count lead, followed by actions and a compact paginated list; detail opens a readable question/answer/media surface. Maintain 8/16/24/32 spacing, semantic status and focus states, existing `admin-*` components, and restrained motion. Avoid giant cards, raw release JSON, invented difficulty, and exposing private storage paths.
